## 2026-11-13 — Toolbox POD MCP

[PR #15](https://github.com/yifeizhangcs/awesome-agentic-commerce/pull/15) by [coltonfitzgerald](https://github.com/coltonfitzgerald) was merged with a shorter entry in Part II: Retail Shopping & Personal Assistants. It is a hosted print-on-demand integration, not a payment protocol, research paper, or open-source server implementation.

- **Order vs. payment:** The [provider tool reference](https://toolboxpod.com/docs/mcp) and live tool definitions distinguish nonbinding estimates, unpaid draft creation (`create_order`), checkout-link handoff (`get_checkout_link`), and real card charges (`purchase_order`, `retry_order`). Draft creation is a write but does not charge. Checkout-link retrieval does not charge either.
- **Documented permissions:** Managers can prepare orders but cannot pay; Viewers have read access. Agent payment requires an Owner connection, a saved card, and an Owner-configured spending limit. Per-order and monthly limits are supported. The default when payment is enabled still sends the Owner to the website for each order unless that setting is changed. ChatGPT and Claude web/desktop are documented as checkout-link-only for payment. The [vendor plugin guidance](https://github.com/Toolbox-POD/toolbox-pod-mcp/blob/main/skills/toolbox-pod/SKILL.md) asks for explicit confirmation before order writes and payment; tool hints and plugin instructions are not a universal enforcement guarantee.
- **Verified boundary:** Public MCP initialization and tool listing responded successfully. OAuth discovery advertises separate `orders:prepare` and `orders:purchase` scopes. An anonymous `whoami` call returned HTTP 401 `missing_token`. The hosted backend is not public, so role checks, spending-limit enforcement, and client-specific behavior were not independently exercised. No account was connected and no order, checkout link, or payment was created.

### Evidence and editorial decisions

- **TaoLive:** [Official arXiv record](https://arxiv.org/abs/2608.15763), v4 dated 2026-09-11. Title: *Training Agents to Evolve with Their Harness: TaoLive Digital Avatar Agent Technical Report*. Authors: TaoLive AIGC LLM Team: Yuhan Sun, Wenhao Lin, Yongdong Luo, Yibo Hu, Meiguang Jin, Junfeng Ma, Weihang Pan, Jiaxin Zhao, and Zulong Chen. Status: arXiv technical report/preprint, 2026; no formal acceptance is claimed. The abstract describes Skills, Hooks, prompts, tools, Harness-Aware Training, Taobao Live deployment, and positive online A/B results for item-page views. It directly supports merchant-side engagement. The second entry is intentional lifecycle/thematic cross-listing. The contributor's September 11 follow-up was acknowledged in the response.
- **AgentServices:** [Canonical repository](https://github.com/vbkotecha/agentservices-api) and [official site](https://agentservices.to). The documentation describes paid API calls using x402 USDC micropayments on Base and MCP discovery. Classification: enabling infrastructure/product resource, not a paper or a new protocol standard. PR #5 changes one file with +183/-347 lines and replaces much of the literature collection with an x402 directory. Only the proposed resource was retained. Endpoint/tool counts and unverified adoption claims were omitted. No payment was made or settlement tested.
- **Packrift:** [Canonical repository](https://github.com/Packrift/packrift-mcp). Documentation lists live catalog search, pricing/stock lookup, packaging fit, shipping estimates, checkout URLs, and quote handoff. It explicitly states that its tools are read-only and never place an order or take payment. Classification: industry integration and shopping infrastructure. Moved from the proposed Protocols & Standards placement to Retail Shopping & Personal Assistants; the original context-card URL was replaced with the current repository.
- **NotFair:** [Current Google Ads MCP documentation](https://github.com/nowork-studio/google-ads-mcp). The documented flow reads account data, proposes changes, requests human approval, and executes approved Google Ads writes. Classification: industry integration/enabling infrastructure for merchant advertising. The public repository is a setup guide, so it is not described as an open-source implementation of the hosted backend. The proposed `toprank` reference was updated. Approval behavior is documented guidance, not independently verified enforcement.
- **SkillHub Pay Adapter:** [TANCO publisher repository](https://github.com/tancoai/tangke-skillhub), [published Skill list](https://github.com/tancoai/tangke-skillhub/blob/main/SKILLS.md), [original suggested Skill page](https://skillhub.cn/team-skills/tencent-skillhub-pay-adapter), and [publisher page](https://skillhub.cn/enterprise/org-j3zmzop1). Classification: industry/workflow context for paid Skills. The publisher documentation discusses package, service, approval, payment, fulfillment, settlement, and funds state boundaries. The original Skill page timed out during verification; the README therefore links to the stable publisher repository. Inclusion was approved by the maintainer, with TANCO identified as publisher and Tencent SkillHub as platform. It is not labeled a Tencent-operated payment rail, standard, or peer-reviewed paper.
